在 Clash 里选中 Hysteria 2 节点后，浏览器的请求要经过本机代理、远端节点和 VPS 出口。浏览器可能用 TCP 访问 HTTPS 网站，本机与 VPS 之间却走 UDP。域名可以解析，节点也能显示在列表中，连接仍可能超时。

理解这套系统，可以从三个问题入手：流量怎样进入 Clash，Clash 怎样把它送到 VPS，VPS 又怎样访问目标网站。

## 一、先弄清什么是协议

网络上的两个程序要交换数据，必须知道对方发来的字节代表什么、什么时候可以发、收到后怎样回应。**协议就是双方共同遵守的通信规则。** HTTP 规定怎样表达网页请求和响应。DNS 规定怎样查询域名记录。Hysteria 2 规定代理客户端怎样认证、怎样告诉服务器要连接哪个目的地，以及后续数据怎样转发。

软件是对这些规则的实现。Chrome 和 Firefox 都可以使用 HTTP，Hysteria 官方客户端和 Mihomo 都可以实现 Hysteria 2。实现可以不同，只要通信双方支持兼容的协议和参数，就有可能互通。YAML 则是配置文件格式，用于告诉软件要启用什么功能和填写哪些参数。

| 层次或用途 | 常见例子 | 主要回答的问题 |
| --- | --- | --- |
| 本地链路 | 以太网、Wi-Fi | 这段本地链路怎样传递数据 |
| 网络层 | IPv4、IPv6 | 数据发往哪个 IP，路由器怎样逐跳转发 |
| 传输 | TCP、UDP、QUIC | 两端程序如何收发数据，是否需要可靠交付和流控制 |
| 安全 | TLS | 如何验证对方身份、协商密钥并保护数据 |
| 应用与代理 | HTTP、DNS、SOCKS5、Hysteria 2 | 怎样请求网页、查询域名，或请代理转发连接 |

这张表按用途理解即可。现实中的协议会复用上下层的功能。例如 QUIC 运行在 UDP 之上并集成 TLS，HTTP/3 又用 QUIC 传输 HTTP 请求。

### 封装是怎么回事

以客户端向 VPS 发出一个 HY2 数据包为例。代理协议表达要进行的操作，QUIC 对需要发送的数据进行加密并组织成分组，UDP 加上源端口和目标端口，IP 加上源地址和目标地址，本地链路再把数据送往下一跳。VPS 收到后逐层处理。目标网站返回的响应也会经过类似过程，只是由 VPS 经已建立的代理连接发回客户端。

[RFC 8200：IPv6](https://www.rfc-editor.org/rfc/rfc8200.html) · [RFC 9110：HTTP 语义](https://www.rfc-editor.org/rfc/rfc9110.html) · [RFC 9000：QUIC](https://www.rfc-editor.org/rfc/rfc9000.html)

## 二、HY、HY2 和其他代理协议是什么

### HY2 节点究竟是什么

HY 一般是 Hysteria 的缩写，出现在节点名称中也可能只是管理员的命名。HY2 明确指 Hysteria 2。Hysteria 1 和 2 的协议不兼容，客户端和服务端要选用相同一代。判断一份 Mihomo 配置是不是 HY2，可以看实际字段是否为 `type: hysteria2`。名称写「HY2」只会改变界面上的显示。

**节点是客户端用来连接某个远端出口的一组参数。** 一条典型的 HY2 节点记录包含服务器域名或 IP、UDP 端口、认证信息、TLS 相关参数。 `hysteria2://` 链接可以编码单个节点的连接参数。Clash 的 HTTPS 订阅是客户端下载配置的入口，下载得到的 YAML 可以包含多个节点以及分流规则。订阅本身走 HTTPS，节点连接再使用各自的代理协议。

### Hysteria 2 怎样接手一个请求

1. 客户端向节点地址发起 QUIC 连接，完成 TLS 握手与服务器身份校验。
2. 客户端提交代理认证信息。服务端根据配置中的共享密码或独立账号决定是否允许使用。
3. 客户端告诉服务端要连接的目的地址，比如一个域名加 TCP 443。服务端打开到目标的连接，再把双方的数据转发起来。
4. 如果应用需要代理 UDP，HY2 也能通过其 UDP 会话机制转发数据报。应用侧转发 UDP 和节点自身借 UDP 传输是两个层次，客户端及服务端配置仍须允许对应的功能。

### 常见类型分别适合拿来做什么

| 类型 | 怎么使用 | 典型连接特征 |
| --- | --- | --- |
| HTTP 代理 | 浏览器或应用把 HTTP 请求交给代理，访问 HTTPS 时常用 CONNECT 建立隧道 | HTTP 代理入口的安全性取决于是否加密，以及它是否只在本机等可信环境使用 |
| SOCKS5 | 通用的应用代理接口，可请求代理连接目标，也定义了 UDP 转发方式 | 常出现在客户端的本地监听端口，协议自身没有统一的传输加密 |
| Shadowsocks | 客户端用约定的加密方式把请求发给远端代理 | 两端要匹配加密方法和密钥。具体版本可支持 TCP 和 UDP 转发 |
| VMess / VLESS | 常见于 V2Ray、Xray 生态，负责在代理客户端与服务端之间传送请求 | VMess 定义自身的认证与加密。VLESS 部署还要看选用的传输和安全设置 |
| Trojan | 以密码认证连接远端代理，常与 TLS 配合 | 节点参数需要匹配服务端的认证和 TLS 设置 |
| Hysteria 2 | 基于 QUIC 的远端代理协议，可转发 TCP 连接和 UDP 数据报 | 通常需要客户端到服务端的 UDP 路径可用 |
| WireGuard | 在设备间传递加密的 IP 数据包，可用于组网或配置互联网出口 | 使用 UDP，依靠密钥和路由配置确定对端和可达网段 |

阅读节点配置时，先看代理协议，再看外层传输、安全设置和认证。比如 VLESS 是代理协议，WebSocket 可以承担外层传输，TLS 保护连接，三者可能同时出现在同一条节点配置里。至于选哪类协议，要结合两端软件的兼容性、所在网络对 TCP 或 UDP 的可达性，以及你需要应用分流还是 IP 层组网。

[Hysteria 1 与 2](https://hy2.app/docs/misc/2-vs-1/) · [Hysteria 2 协议说明](https://hy2.app/docs/developers/Protocol/) · [Xray 协议说明](https://xtls.github.io/en/development/protocols/) · [WireGuard 协议说明](https://www.wireguard.com/protocol/)

## 三、一次网页访问经过哪些组件

```text
浏览器 → Mihomo 接收请求并匹配规则
           ├─ DIRECT → 本地网络 → 目标网站
           └─ HY2 → QUIC / UDP → VPS 上的 Hysteria 2 → 目标网站
```

Clash Verge Rev 是操作界面。它负责导入配置、选择节点和展示连接。真正监听本地端口、处理 DNS、匹配规则和建立出站连接的是 Mihomo，也就是由 Clash.Meta 演进而来的内核。

Hysteria 2（简称 HY2）是这条路径中的代理协议，也有独立的客户端和服务端实现。在这里，Mihomo 自己实现了 Hysteria 2 客户端功能，VPS 上运行 Hysteria 2 服务端。客户端把目的地址和数据交给服务端，服务端向目的地发出请求或转发数据。经代理发送的请求，目标服务通常看到的是 VPS 的出站地址。

### 系统代理、TUN 和 VPN 有什么区别

系统代理告诉支持该设置的应用把请求交给本地代理端口。浏览器通常能使用它，但有些应用会按自己的设置联网。TUN 通过虚拟网卡和路由表接收 IP 流量，系统哪些流量会经过它，取决于路由、排除项和平台权限。流量进入 TUN 后，Mihomo 仍可按规则选择直连或代理。

组网型 VPN 还可以给设备分配隧道地址，让两台设备通过私网路由互访。例如，用 NetBird 连接家里的电脑和外出的手机，手机可以访问电脑的私有地址。用 HY2 借 VPS 出口访问网站，关注的是请求从哪里出网。两种用途也可以并存。

[Mihomo TUN 配置](https://wiki.metacubex.one/en/config/inbound/tun/) · [Hysteria 2 协议说明](https://hy2.app/docs/developers/Protocol/)

## 四、TCP、UDP 和 QUIC 怎样分工

TCP 提供可靠、有序的字节流，负责确认、重传和拥塞控制。UDP 提供数据报传输，应用可以自行决定如何处理丢包和顺序。QUIC 运行在 UDP 上，集成 TLS 1.3，并提供多条独立的可靠流。同一 QUIC 连接中，一条流发生丢包时，其他流通常无需等它补齐才能交付数据，不过仍会受到共享链路与拥塞控制的影响。

Hysteria 2 用 QUIC 在客户端和服务端之间传输代理流量。假设浏览器通过 TCP 访问一个 HTTPS 网站，VPS 可以照常向网站建立 TCP 连接，中间的客户端到 VPS 这一段仍然走 QUIC/UDP。于是，打开网页用到 TCP 和节点端口必须放行 UDP 可以同时成立。

### 为什么有些线路上 HY2 很快

吞吐量取决于链路容量、往返延迟、丢包、拥塞和 VPS 出口。Hysteria 2 可按配置使用 BBR 等拥塞控制，也可以在指定带宽时使用 Brutal。Brutal 会尝试维持设定速率，并通过额外发送补偿丢包。手填的带宽高于链路持续承载能力，可能加重排队、丢包和流量消耗。测速时应区分延迟、持续吞吐和高峰期表现。

[RFC 9000：QUIC](https://www.rfc-editor.org/rfc/rfc9000.html) · [Hysteria 2 拥塞控制](https://hy2.app/docs/advanced/Full-Server-Config/#congestion-control-details)

## 五、TLS 证书、SNI 和节点密码各验证什么

客户端要知道自己连到的是预期的代理服务器，服务端也要确认客户端有权使用代理。前者由 TLS 证书验证承担，后者由代理认证承担。

| 名词 | 在这条连接里的作用 |
| --- | --- |
| TLS | 为客户端到代理服务端的连接提供加密和完整性保护，并支持验证服务端身份 |
| 证书 | 将域名等身份与公钥绑定。客户端检查名称、有效期和信任链 |
| SNI | 客户端在握手时告诉服务端希望连接的域名，服务端可以据此选择证书 |
| 私钥 | 由服务端持有，用于证明它有权使用相应证书 |
| 代理密码 | 服务端用它决定是否接受客户端连接 |

受信任 CA 签发的证书通常可以用客户端已有的信任链验证。自签名证书需要额外建立信任，例如让支持此方式的客户端校验预先通过可信渠道取得的 SHA-256 证书指纹。指纹对应具体证书，换证后要同步更新固定值。若遇到证书错误，应核对连接名称、证书链和信任设置。

ACME 是自动化申请和续期证书的协议。域名可以通过 DNS 记录证明控制权，也可以按所选挑战方式在指定端口响应验证。Hysteria 2 可自行通过 `acme` 获取证书，也可以用 `tls` 读取已经签发的证书文件。服务配置要选定一种来源。

访问 HTTPS 网站时还会有应用到网站的独立 TLS 会话。VPS 转发应用数据时通常可以看到建立连接所需的目的信息，网站 HTTPS 正文仍由应用和目标网站之间的 TLS 保护。普通 HTTP 正文则缺少这层保护。

[Hysteria 2 证书配置](https://hy2.app/docs/advanced/Full-Server-Config/#tls) · [Mihomo TLS 字段](https://wiki.metacubex.one/en/config/proxies/tls/)

## 六、DNS 会在哪些环节参与代理

先区分两个域名。节点域名用于找到 VPS，目标域名用于找到你要访问的网站。它们可能在不同设备上、由不同的解析器查询。节点域名解析错了，代理连接就会发往错误地址。节点已经连通但某个网站打不开，还可以检查目标域名如何解析、代理收到的是域名还是 IP。

DNS 查询一般由本机交给递归解析器。解析器在缓存未命中时查找权威记录，再返回结果。DoH 将本机或客户端发往 DNS 解析器的查询放进 HTTPS 请求中，保护的是这段查询通道。

Mihomo 的 Fake-IP 用在本地 DNS 和流量接管之间。假设浏览器查询一个网站域名，Mihomo 可以先返回一个虚拟 IP，并保存它与域名的映射。浏览器连接这个虚拟 IP 时，Mihomo 查表取回域名，再按域名规则决定出站。应用收到的虚拟地址属于本地处理的一部分，最终连接仍要解析或使用目标的真实地址。把握这层映射，就能理解为什么 DNS 配置和分流规则经常要一起看。

## 七、一份 Clash 配置是怎样生效的

YAML 负责描述配置，缩进决定字段属于哪一层。看懂配置可以按 Mihomo 处理连接的顺序来读。

1. **入口。** 本地代理端口接收应用的 HTTP 或 SOCKS 请求，或者由 TUN 接收流量。
2. **规则。** 在规则模式中，Mihomo 根据域名、IP 等条件匹配策略。放在末尾的 `MATCH` 处理前面没有命中的请求。
3. **策略组。** 规则可以指向一个代理组。组里可以让用户手选节点，也可以按健康检查结果选择可用节点。
4. **节点。** `type: hysteria2` 指定出站协议。`server` 和 `port` 指向 VPS，`sni` 对应预期的 TLS 名称，`password` 提供节点认证。

节点显示在界面里，说明配置已能被载入。实际使用时还要确认应用进入了 Mihomo、规则命中了预期策略、策略组选中 HY2，以及远端握手成功。「连接」页可以用来观察具体请求选了哪条路径。

[Mihomo 快速配置](https://wiki.metacubex.one/en/start/quick-config/) · [Mihomo Hysteria 2 节点字段](https://wiki.metacubex.one/en/config/proxies/hysteria2/)

## 八、IP、端口、NAT 和 VPS 出口

IP 地址用来标识网络中的接口，端口用来让操作系统把 TCP 或 UDP 数据交给正确的程序。一个常见的连接识别方式是五元组，由源 IP、源端口、目的 IP、目的端口和传输协议组成。你在节点里配置的 8443 是服务端端口，客户端通常由系统为每条连接选用一个临时端口。TCP 8443 和 UDP 8443 属于不同的端口空间。

家里的电脑可能使用 `192.168.1.10` 这样的私有 IPv4。家庭路由器做 NAT 时，会把流量的来源地址与端口映射到对外的一组地址与端口，收到响应再按映射送回电脑。对于从外部主动发来的 UDP 包，若目标服务器位于 NAT 后面，往往还需要端口映射或其他可达方案。云主机的公网 IP 也可能由云平台映射到本机私网接口，所以操作系统显示私网地址时，应到云控制台核实公网地址和映射。

VPS 是一台运行在云平台上的虚拟服务器。它能作为远端出口，是因为它能接收客户端连接，并以自己的网络路径访问目标。买了某地区的 VPS，只能确定服务方提供的部署区域。实际出口 IP 归属、到客户端的路由和带宽表现还受运营商、目标服务和机房网络影响。

安全组设在云平台的入站边界，UFW 等工具控制操作系统防火墙，服务监听决定有没有程序接收对应流量。排查时依次问三件事：包能不能到机器、机器放不放行、进程有没有在正确的地址和协议上接收。

[RFC 1918：私有 IPv4 地址](https://www.rfc-editor.org/rfc/rfc1918.html) · [RFC 4787：UDP NAT 行为](https://www.rfc-editor.org/rfc/rfc4787.html)

## 九、节点超时时，怎样确定是哪一层出了问题

端口要连同传输协议一起看。TCP 443 可以给普通 HTTPS 使用，UDP 443 可以给 HTTP/3 使用。如果 Caddy 已经绑定了 UDP 443，Hysteria 2 可以改用 UDP 8443，客户端和入站规则也要一起改。服务器显示 `0.0.0.0:8443` 时，表示套接字绑定了本机全部 IPv4 接口。云安全组和系统防火墙仍分别决定入站流量是否能通过。

Linux 的 `ss` 对未关联固定对端的 UDP 监听套接字通常显示 `UNCONN`。这在服务端属于正常状态。原记录里，Clash 一度显示超时，而 systemd 和 `ss` 已确认服务在运行、UDP 8443 有监听。后来连接成功，记录没有留下足以确认最终根因的信息。

| 手上已有的证据 | 下一步要验证什么 |
| --- | --- |
| 界面显示节点 | 看服务状态，核对实际监听地址、端口和协议 |
| UDP 套接字已监听 | 发起连接，同时在 VPS 观察是否收到 UDP 包 |
| VPS 没收到包 | 核对 DNS、目的端口、安全组和客户端网络，必要时换一条网络做对照 |
| VPS 收到包 | 对照服务端与客户端日志，检查返回路径、QUIC 握手、证书和认证 |
| 节点可用，某个应用异常 | 核对应用是否进入 Clash、命中的规则、目标 DNS 和 VPS 出站连通性 |

TCP 端口探测适合验证 TCP 连通性。检查 HY2 的 UDP 路径，最好用一次真实节点测试配合服务端抓包和日志。看到双向数据包后，仍需查看握手与认证结果。每轮只改一个变量，才能判断是哪一次改动影响了连接。

[Hysteria 2 官方排障](https://hy2.app/docs/advanced/Troubleshooting/)

## 十、从打开网页到收到响应，完整走一遍

假设浏览器通过系统代理访问一个 HTTPS 网站，Mihomo 规则命中 HY2，节点域名为 `hy.example.com`，端口为 UDP 8443。这些地址和端口用来举例。

1. 浏览器连接本机的代理端口，提出到目标网站 443 的连接请求。网站的域名可以随代理请求传给 Mihomo。
2. Mihomo 匹配规则和代理组，选中 HY2。第一次连接节点时，需要先获得 `hy.example.com` 的地址。如果已有可复用的连接，可继续使用现有会话。
3. Mihomo 向 VPS 发送 UDP 数据。数据经过本地网络和互联网路由，穿过云安全组和服务器防火墙，到达 Hysteria 2。
4. QUIC 和 TLS 建立连接，随后服务端验证代理认证信息。到这里，客户端才具备使用代理的条件。
5. Hysteria 2 根据目标域名或 IP 向网站建立出站连接。浏览器通过这条代理路径与网站建立自己的 HTTPS 会话。
6. 网站从 VPS 出站连接返回数据，Hysteria 2 再经 QUIC 送回 Mihomo，由 Mihomo 交还浏览器。

把每个阶段拆开，也能看出谁掌握哪些信息。接入网络可以观察到设备连接了哪个 VPS，以及流量的时序和规模。VPS 通常知道代理客户端来源和目标连接信息。目标网站通常看到 VPS 出口，但仍可通过登录账号、Cookie 等识别用户。TLS 保护特定连接上的内容，使用代理也只改变被代理流量的出站路径。
