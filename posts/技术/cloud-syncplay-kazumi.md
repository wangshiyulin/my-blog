# 在Ubuntu云服务器上搭建Syncplay服务端，并接入Kazumi实现远程同步看番

最近和几个朋友一起追新番，但在不同城市、不同设备上同步观看体验一直不太好。

试过各种方案——远程桌面、共享屏幕、甚至手动倒计时按播放键——要么延迟高，要么操作繁琐。

直到接触了 [Syncplay](https://syncplay.pl/)，才发现这才是远程同步观影的正确姿势。

更惊喜的是，用来看番的开源软件 [Kazumi](https://github.com/Predidit/Kazumi) 原生支持 Syncplay，免去额外客户端的麻烦。

本文就来详细记录我在 Ubuntu 云服务器上部署 Syncplay 服务端的全过程，以及如何配置 Kazumi 客户端，实现真正无缝的多端同步观看。

## 为什么需要自建 Syncplay 服务端？

Syncplay 官方提供公共服务器（如 `syncplay.pl:8999`），但公共服务器有用户数限制、不稳定、且无法控制安全策略。自建服务器可以：

- 自定义端口和加密（TLS）
- 绑定域名，长期可用
- 完全掌控访问权限（设置密码、限制房间数）
- 降低延迟（选择离用户最近的云服务器）

如果你已经在用 Kazumi 看番，那么只需配置一下服务器地址，其他播放器（如 mpv、VLC）也可通过 Syncplay 插件加入。

## 环境准备

- 一台 Ubuntu 22.04/24.04 云服务器（本文以腾讯云轻量应用服务器为例，1核1G 足够）
- Python 3.8+（Ubuntu 默认已装）
- 基本的防火墙管理权限（iptables 或 ufw）
- 域名（可选，用于 TLS 证书申请）

## 第一步：安装 Syncplay 服务端

拉取源代码：

```
git clone https://github.com/Syncplay/syncplay.git
```

启动服务器：

```
cd syncplay
./syncplayServer.py
```

能看到以下输出即代表成功启动：

```
Welcome to Syncplay server, ver. 1.6.6
PLEASE NOTE: To allow room operator passwords generated by this server instance to still work when the server is restarted, please add the following command line argument when running the Syncplay server in the future: --salt NIJGVMHKOC
```

说明服务器已经正常运行了。此时其实就可以使用了：无密码，端口默认8999。不过有点粗糙，这里xianCtrl+c停止

## 第二步：配置并启动服务端

Syncplay 服务端默认监听 `0.0.0.0:8999`。

创建一个配置文件（也可直接用命令行参数）。

这里我们创建一个 systemd 服务，便于开机自启和管理。

### 1. 创建 systemd 服务文件

```bash
sudo vim /lib/systemd/system/syncplay.service
```

写入以下内容：

```ini
[Unit]
Description=Syncplay Server
After=network.target

[Service]
WorkingDirectory=/home/syncplay
User=nobody
Group=nogroup
Type=simple
ExecStart=/home/syncplay/syncplayServer.py --salt WCRKULYHPV --port 8999 --password myPassword
ExecStop=/bin/kill -s HUP $MAINPID
PIDFile=/home/syncplay/syncplay.pid
RestartSec=15
Restart=always

[Install]
WantedBy=-user.target
```

### 3. 启动并启用服务

```bash
sudo systemctl daemon-reload
systemctl enable --now syncplay
sudo systemctl status syncplay
```

这将使syncplay开机自启，并且立即运行。

查看状态，看到 `active (running)` 即成功。

## 第三步：配置防火墙

云服务器通常有安全组规则，同时服务器内部防火墙也要放行。假设你使用的是 ufw：

```bash
sudo ufw allow 8999/tcp
sudo ufw reload
```

如果是云平台（如腾讯云），记得在安全组中添加入方向 TCP 8999 端口。

## 第四步：在 Kazumi 中配置 Syncplay 连接

Kazumi（基于 mpv）内部集成了 Syncplay 客户端。启动 Kazumi 后，找到一部番剧进入观看。

1. 找到右上角有-一起看-选项。
2. 切换服务器 -> 自定义服务器地址：`你的服务器IP:8999`（或域名:8999）。
3. 保存并加入房间即可。

连接成功后，Kazumi 状态栏会显示 Syncplay 已连接。你可以让好友输入同样的服务器和房间号一起观看同一视频源。

## 第五步：测试与常见问题

### 测试方法

1. 在两台设备上安装 Kazumi，连接同一服务器。
2. 打开同一个视频。
3. 一台设备播放，另一台应自动同步。

### 常见问题

**问题1：连不上服务器**  
- 检查防火墙（服务器安全组和 ufw）是否放行 8999 端口。
- 确认 systemd 服务是否运行：`sudo systemctl status syncplay`  
- 使用net 测试：`telnet 服务器IP 8999`。如果通，则服务正常。

**问题2：连接成功但无法同步**  
-确保所有客户端使用同一视频源（同一文件或同一在线 URL）。Syncplay 基于文件名

### 服务端自定义参数
--port [port] – 自定义端口
--isolate-room – 如果有这一项，那么用户将无法看到除了他们所在的房间以外的其他房间中的用户的信息。
--password [password] – 为Syncplay服务器设置密码，只有通过密码才能连接上服务器。
--salt [salt] – 随机的 salt(http://en.wikipedia.org/wiki/Salt_(cryptography)) 字符串 used to generate controlled room passwords – needs to be the same for controlled room passwords to work between server instances. （不太明白）
--motd-file [filepath] – 自定义motd文件的目录，这个可以在进入房间时显示欢迎词
--disable-ready – 禁用准备指示功能
--disable-chat – 禁用聊天功能
--max-chat-message-length – 限制聊天允许发送字符数量的最大值
--max-username-length – 限制用户名字母数量的最大值
--stats-db-file [filepath] – 使用 SQLite db 记录服务器状态
--tls [path] – 使用在特定目录的证书来启动TLS功能. 看更多教程： https://github.com/Syncplay/syncplay/wiki/TLS-support。
